What CRUD Means
----------------
    C = Create  → Add new data       (POST + INSERT)
    R = Read    → Get existing data   (GET + SELECT)
    U = Update  → Modify data         (PUT + UPDATE)
    D = Delete  → Remove data         (DELETE + DELETE)

Almost every web application is based on CRUD operations.


Complete Feature List
---------------------
    ✓ User creation         → POST /api/users
    ✓ Task creation         → POST /api/tasks + HTML form
    ✓ Task listing          → GET /api/tasks + HTML page
    ✓ Single task retrieval → GET /api/tasks/<id> + HTML page
    ✓ Task update           → PUT /api/tasks/<id> + HTML form
    ✓ Task deletion         → DELETE /api/tasks/<id> + HTML link
    ✓ Task filtering        → GET /api/tasks?status=pending
    ✓ Task searching        → GET /tasks/search?q=flask

    ✓ HTML Interface        → Web forms for browser-based use


How Everything Connects
-------------------------

    Layer 1 — Client (Browser or Postman)
        Sends HTTP requests, receives responses

    Layer 2 — Routes (app.py, routes/*.py)
        Matches URLs to functions
        Reads request data
        Calls business logic
        Returns responses

    Layer 3 — Forms (forms.py)
        Validates HTML form submissions
        CSRF protection

    Layer 4 — Models (models.py)
        Converts database rows to dictionaries
        Defines valid statuses

    Layer 5 — Database (database.py)
        Connects to SQLite
        Executes SQL queries
        Returns data

    Layer 6 — SQLite (tasks.db)
        Stores data permanently on disk


The Full Request Lifecycle
---------------------------
    Example: User creates a task via HTML form

    1. User visits /tasks/add (GET)
       → Flask serves add_task.html with empty form

    2. User fills in title and description, clicks Submit

    3. Browser sends POST /tasks/add with form data

    4. Flask routes to add_task() in task_routes.py

    5. AddTaskForm validates the data
       - If invalid → re-render form with error messages
       - If valid → continue

    6. Route calls create_task(title, desc, status) in database.py

    7. database.py runs: INSERT INTO tasks VALUES (?, ?, ?)

    8. SQLite saves the data to tasks.db

    9. Route does: flash("Task created!", "success")

    10. Route does: redirect(url_for("tasks.list_tasks"))

    11. Browser follows redirect to /tasks

    12. Flask renders tasks.html with all tasks from database

    13. User sees the task list with a success message


Testing with Postman
---------------------
    Create a Postman collection with these requests:

    1. Create User
       POST http://localhost:5000/api/users
       Body: {"name": "Alice", "email": "alice@email.com"}

    2. Create Task
       POST http://localhost:5000/api/tasks
       Body: {"title": "Learn Flask", "user_id": 1}

    3. List Tasks
       GET http://localhost:5000/api/tasks

    4. Get Single Task
       GET http://localhost:5000/api/tasks/1

    5. Update Task
       PUT http://localhost:5000/api/tasks/1
       Body: {"status": "completed"}

    6. Delete Task
       DELETE http://localhost:5000/api/tasks/1

    7. Filter Tasks
       GET http://localhost:5000/api/tasks?status=pending
