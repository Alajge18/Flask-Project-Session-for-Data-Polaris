Why Project Structure Matters
------------------------------
A well-organized project is:
  ✓ Easy to understand
  ✓ Easy to maintain
  ✓ Easy to extend
  ✓ Professional and portfolio-ready

BAD structure (everything in one file):
    app.py    ← 500+ lines: routes, database, forms, validation

GOOD structure (separation of responsibilities):
    app.py           ← Application setup + blueprint registration
    database.py      ← Database operations
    models.py        ← Data conversion helpers
    forms.py         ← Form definitions
    config.py        ← Configuration
    routes/          ← Route handlers (organized by feature)

Separation of Responsibilities
-------------------------------
Each file has ONE job:

    File              Responsibility
    ────              ──────────────
    app.py            Create app, register blueprints, start server
    config.py         Store configuration (SECRET_KEY, DATABASE)
    database.py       Talk to SQLite (SQL queries)
    models.py         Convert data formats (Row → Dict)
    forms.py          Define and validate forms
    task_routes.py    Handle /tasks and /api/tasks URLs
    user_routes.py    Handle /users and /api/users URLs
    templates/        Display HTML pages
    static/           CSS, JavaScript, images

This means:
    - app.py doesn't know SQL
    - database.py doesn't know about Flask routes
    - forms.py doesn't know about the database
    - Each piece can be changed INDEPENDENTLY


Flask Blueprints
-----------------
Blueprints organize routes into MODULES (like mini-apps).

Without blueprints (all in app.py):
    @app.route("/tasks")           ← All routes in one file
    @app.route("/tasks/<id>")
    @app.route("/api/tasks")
    @app.route("/users")
    @app.route("/api/users")

With blueprints (organized by feature):
    # routes/task_routes.py
    task_bp = Blueprint("tasks", __name__)

    @task_bp.route("/tasks")
    def list_tasks(): ...

    # routes/user_routes.py
    user_bp = Blueprint("users", __name__)

    @user_bp.route("/users")
    def list_users(): ...

    # app.py
    app.register_blueprint(task_bp)
    app.register_blueprint(user_bp)


How Data Flows Through the Architecture
-----------------------------------------
    1. Browser sends request: GET /tasks
    2. Flask finds the matching route in task_routes.py
    3. Route function calls database.py: get_all_tasks()
    4. database.py runs SQL: SELECT * FROM tasks
    5. SQLite returns rows from tasks.db
    6. database.py returns rows to route function
    7. Route converts rows to dicts using models.py
    8. Route renders template with data
    9. Flask sends HTML response to browser
